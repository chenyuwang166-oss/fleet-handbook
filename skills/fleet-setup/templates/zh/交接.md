# 交接

只在末尾追加，保留旧记录。每节标题写明接手岗位和任务；读取时找交给本岗位或本任务的最新一节，不按时间直接取最后一条。分不清是不是自己的，先问。压缩摘要只作线索，须核对项目卡、匹配交接和实际状态。判断分别写“看到的”“推断的”“猜的”。

人的重要决定、新规矩和刚起的后台任务当场记入决定记录或交接；收工时核对。项目卡只由项目经理维护，其他岗位在这里或决定记录中提出改动。

## 〔待定：日期｜接手岗位｜任务〕

- 做到哪：〔待定：已存在的产物、验证结果；运行完成、交付齐全、质量合格分别写〕
- 下一步：〔待定：接下来排着的几件，按先后列，排到节点之后；第一件卡住（比如等人定）时先做哪件〕
- 卡在哪：〔待定：缺材料、缺授权或异常；没有就写无〕
- 谁接、何时接：〔待定：接手岗位与触发时间或条件〕
- 成功时：〔待定：如何识别、接下来交谁〕
- 失败时：〔待定：如何识别、保留什么、交谁判断〕
- 恢复命令：〔待定：工作目录、前置核对、可直接执行的命令；无需运行则写明〕
- 正在运行：〔待定：任务标识、启动时间、状态证据、成功与失败的识别方法和续接方式；没有则写无〕
- 项目卡改动建议：〔待定：交项目经理核对的改动、依据；没有则写无〕
- 等人定：〔待定：具体动作、倾向与理由〕
