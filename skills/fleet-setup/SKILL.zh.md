# 搭建项目骨架

从项目的长期目标出发，找出下一步有人等着定的事。只为这一关定分工，写清谁交证据、谁能验收或退回、哪些事留给人定。同类活反复出现时，再提议设常岗。要给手册反馈时，直接照[给舰队手册提 issue](#给舰队手册提-issue)一节做。

项目经理负责分工、写任务书和安排验收。成员执行，指定的审核岗位核对成品。按名册中的模型分工表写清每类活的执行岗位、模型及厂商、程序和验收人。

先读项目已有的材料，再一次问一件。这个项目要持续做成什么，眼下要过哪一关？做到什么样，验收人就能放行？哪些决定要留给读者自己？说明这些回答用来定目标和决定边界，请读者在这里回答当前这一问；每次收到回答先核对，没说清的只追问那一点，再接着问。已有明确答案时复述核对，不重复问，核对后再填项目文件。

以读者指定的项目根目录为工作目录。先看根目录的 `AGENTS.md`、`CLAUDE.md` 和 `fleet/` 的已有文件，保留已有内容，更新时逐项合并。不要替读者覆写已定原则或成员分工。

从 [项目卡模板](templates/zh/AGENTS.md) 起步，建成以下结构：

```text
项目根目录/
  AGENTS.md
  CLAUDE.md
  fleet/
    原则.md
    价值观.md
    成员.md
    决定.md
    机会.md
    交接.md
    审批流.md
    岗位卡/
    任务书/
    交付/
```

项目卡正文只写在根目录 `AGENTS.md`；新建的根目录 `CLAUDE.md` 按 [引用模板](templates/zh/CLAUDE.md) 只写一行 `@AGENTS.md`。文件已存在时分别保留原文，在末尾追加一节“AI 舰队项目卡”：`AGENTS.md` 的新节写项目卡正文，`CLAUDE.md` 的新节只写引用行 `@AGENTS.md`。已有该节时只合并该节，不重复追加，不动其他内容。开始时显式读根目录项目卡，核对宿主是否载入引用。

项目卡第一行原样写模板中的两个动作：重启、换会话或上下文压缩后，先读项目卡和交给本岗位或本任务的最新交接，和实际状态核对，再动手；收工或上下文快满时，先写交接。追加到已有文件时，这句话放在新节正文第一行。其余模板分别复制到 `fleet/`：[原则](templates/zh/原则.md)、[价值观](templates/zh/价值观.md)、[名册](templates/zh/成员.md)、[决定](templates/zh/决定.md)、[机会](templates/zh/机会.md)、[交接](templates/zh/交接.md)、[审批流](templates/zh/审批流.md)。[任务书模板](templates/zh/任务书.md) 用于 `fleet/任务书/`；同类工作反复出现时，再按 [岗位卡](templates/zh/岗位卡.md) 在 `fleet/岗位卡/` 建岗，不为填满组织图而加岗。

项目卡写目标、规矩、进行中、等我定，并附一页内的文件地图。项目卡只由项目经理岗位维护，其他岗位通过交接和决定记录提出改动。压缩摘要只作线索，核对匹配交接和实际状态；分不清交接是不是自己的，说明是哪份交接、为什么要核对，请读者说清它交给哪个岗位或任务，核实对应关系后再继续。重要决定、新规矩和刚起的后台任务当场记，收工时核对。约好每周哪天看机会表，按审批流写明哪些小范围试改由岗位自己定。

成员名册用模板的七列表头，由你问着读者填，一次问一样：先问手里有哪些 AI 工具，再问工具用的是哪些模型、哪家厂商，最后问每种怎么调——命令行的原样命令，或者接口地址、密钥、模型这三个环境变量的名字，不问秘密的值。说明这是为了确定谁能接活，每次收到回答先核对，只接着问缺的那一点。每种调用方式第一次试通前，说明小请求可能花一点钱，请人点头，再用一条不伤东西的小请求试通，比如只请它回“OK”；成功后把已核实的调用方式和试通日期写进名册。试不通就照 [fleet-dispatch](../fleet-dispatch/SKILL.zh.md) 排查，确实需要安装、登录或设变量时，说明缺什么、为什么，一次只带做一步，写清在哪做，能照抄的给原样命令，并说清做完回“好了”还是贴不含秘密的结果；收到回复先用只读检查核实，再继续，仍不通就给下一步，不从头再问。不问密钥、密码的值，也不让人把它们贴出来。只有一家时，名册里第二家写“还没接上”，照样往下搭。岗位和模型分开，写与审由不同厂商承担；第二家还没接上时，独立审核记为待完成。审批流只列事项和谁定，不增加通用审批判据。

原则只写已确认的工作规矩。加新规矩前先问一句：它会让人少被打扰，还是多被打扰？会多打扰人的，先找别的办法。要去掉一条，先弄清它在防什么。价值观先保留空模板，再用 [fleet-values](../fleet-values/SKILL.md) 帮读者讨论；涉及方向由人定，既定方向内的行为条款由审批流里有权的岗位定；不要预填任何现成价值观。待试的改法留在机会表。按审批流应由人决定的事项才列进“等我定”。

搭好后检查根目录项目卡、引用行、原文保留情况、`fleet/` 文件地图、名册中的岗位关系、各任务的交付位置。说清搭了什么，接着围绕读者选的关口走第一单。写第一张任务书给人过目，标出原材料、依赖、验收人和退回条件。派出去、收回成品，有第二家就带着接上，安排不同厂商独立审核，再给下一位写交接。范围变了，在决定记录里保留原标准，告诉受影响的岗位哪些活要重排。要核对汇报关系时，可以画一张包含人的组织图。复用已确认的回答和试通方式，不重复已完成的步骤；跑完、收到、审过分开报，第二家仍没接上时照样推进，并说明独立审核还没完成。带着读者把文件填好，不把要填的表留给人自己填。花钱、对外承诺、删东西、定方向的具体动作先请人同意；需要人配合时照项目卡的规矩一次一步带着做，不问秘密的值。

## 给舰队手册提 issue

人说“给舰队手册提个建议”“给舰队手册报个问题”时，照这一节做。人只让起草，不等于同意发布。

1. 用人说的语言写标题和 Markdown 正文，中英都可以。照下表对应栏目的意思写小标题；装好的技能不需要克隆目录里的模板文件。出了错，要写最少复现步骤、工具和版本、操作系统、用到的 Python 版本。缺关键内容就问，不知道的标明不知道，不编。选填项没有内容就略过。

   | 种类 | 模板文件 | 栏目（网址 ID：意思） |
   | --- | --- | --- |
   | 出了错 | `bug.yml` | `environment`：工具和版本、操作系统、Python；`readme-step`：README 的步骤和命令；`actual-and-expected`：实际与预期；`reproduce`：最少复现步骤 |
   | 用着卡住 | `stuck.yml` | `stuck-step`：README 或技能的哪一步；`stuck-goal`：当时想做什么；`attempts`：试过什么；`time-spent`：卡了多久，选填。不算出错也欢迎。 |
   | 想要什么 | `feature.yml` | `feature-goal`：想做成什么事；`current-way`：现在怎么做、哪里不便；`wanted-help`：希望手册或技能怎么帮忙。不要求实现方案。 |
   | 晒舰队 | `show-your-fleet.yml` | `rule`：可只交一条规矩，写适用什么情况、怎么试的、结果或反例。其余舰队资料均选填。`organization-chart`：`fleet/组织图.md` 或 `fleet/chart.md` 的完整 mermaid 代码块，保留首尾围栏行，也可以贴截图；`fleet-work`：舰队在做什么；`provider-count`：几家模型厂商；`human-decisions`：自己定哪些事；`extra-images`：自测卡、看板截图，选填 |

2. 去掉密钥、令牌、账号、本机路径、人名和不想公开的材料。本机路径换成 `<项目目录>` 这类占位；项目里的私密内容只转述，不整段贴。日志片段和截图也要查有没有敏感内容。保留下文要用的公开仓库地址。给人看之前，通读整份草稿。
3. 先说明 issue 是公开的。先把标题和完整正文原样给人看，说清会怎么提（用人已登录的 `gh` 直接提，或给一个预填链接让人自己点提交；人想自己点，就给链接），再问“这样提吗”，等人明确点头。人修改了就照改，再把完整标题和正文给人看，等人对这一版点头。同意起草不等于同意发布。
4. 人点头后，检查有没有 `gh`，以及 `gh auth status --hostname github.com` 是否成功。有且已登录，就把最终获准、已脱敏的 Markdown 正文写到项目临时目录里的一个新 UTF-8 文件。标题作为一个参数传入，不让 shell 展开其中的内容，运行 `gh issue create --repo chenyuwang166-oss/fleet-handbook --title "<获准标题>" --body-file "<临时正文文件>"`，提完给人 issue 链接。这个命令按正文原样提交，不会补模板栏目。结果不明时先核对是否已经提成，不直接重试，以免重复。

   没有 `gh` 或没登录，就给预填链接，让人自己提交：`https://github.com/chenyuwang166-oss/fleet-handbook/issues/new?template=<模板文件名>&title=<标题>&<栏目-id>=<内容>`。模板文件名和栏目 ID 照上表，用 `urllib.parse.urlencode` 或同等方法编码参数值，包括换行；不要把整条网址编码。网址太长，就只填标题和最要紧的栏目，把其余获准正文给人粘贴。不自动打开或提交。截图要通过网页上传，本机图片路径不能替人上传；需要配图时可给网页表单。
5. 人没明确点头，不提交。提不提、提什么，都由人定。人不想提就停，不把沉默当同意。
