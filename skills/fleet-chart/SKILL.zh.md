# 画组织图
对照项目实际名册核查组织图上的汇报关系。看看板时，把交付和审核记录对起来，查清哪些通过、哪些退回、下一步轮到谁。依据不够时，写明缺哪份记录。中文表头固定为“岗位、部门、汇报给、派驻、怎么调用、做什么、交付写进”，英文为“Role、Department、Reports to、Assigned、How to call、Does、Delivers to”。可调整列顺序，不能缺列或重列。汇报给填另一个岗位，或填“人”（英文也可填 Human）；单元格内竖线写成 `\|`。

从技能包根目录运行，替换输入与输出路径；若输出已存在，先核对是否应另起版本：

```bash
python -X utf8 skills/fleet-chart/scripts/fleet_chart.py /path/to/my-project/fleet/成员.md -o /path/to/my-project/fleet/组织图.md
```

脚本只用 Python 标准库，需要 Python 3.9 以上。缺列、岗位重名、汇报对象不存在、成环或文件读取失败时，退出码为 2，并用一句话指出问题。先核对原表，不能为了出图擅自改汇报关系；关系没有定时，列出涉及的岗位和为什么要人定，请人在这里只回这个岗位的关系，比如“分析员汇报给项目经理”。先核对汇报对象存在、不产生循环，再记入确认过的关系，重新运行；仍有问题就说明下一处，不从头再问。成功退出为 0，省略 `-o` 时输出到终端。

所有成员都画在同一个组织框内，人是其中一员。按名册表头确定图的语言：中文表头的组织框标题写“AI 舰队”，人的节点写“人”；英文表头分别写“AI Fleet”和“Human”，不把两种语言并列写。箭头从汇报对象指向岗位，标签列出岗位、部门、派驻；调用命令和交付路径不进图。用户文字经过 Mermaid 实体转义，不能变成图表语法。

完成后打开生成的 Markdown，对照原表逐岗核对，再在支持 Mermaid 的阅读器中检查显示。需要人协助查看时，写出实际文件路径，说明还要核对显示，请人在自己支持 Mermaid 的阅读器中打开，回“显示正常”或指出第一处问题；先和原表核对回复，再继续。交回文件、检查结果；没有实际渲染时如实说明只完成了源文本核对。

名册读不到或输出写不进去时，先核对项目内的准确路径。确实要人配合时，说明当前原因，只给对应的一步：在自己的文件管理器中打开名册，回“能打开”或“找不到”；在那里新建指定的输出目录，回“建好了”；或在这里回一个项目内已有且可写的输出目录。只选当前受阻的一步；先只读核对返回的路径或目录，再填好实际路径重跑命令。不更改项目外目录，不索要密钥或密码，不从头再问。定方向、对外承诺、花钱、删东西先由人点头。

生成四块本地看板：从技能包根目录运行 `python -X utf8 skills/fleet-chart/scripts/fleet_board.py --project <项目目录>`，按项目文件名自动选择中文 `fleet/看板.html` 或英文 `fleet/board.html`，判断不出用中文；`--lang zh|en` 可覆盖。依次显示“等你、在干的活、做成了、谁在干活”：项目卡待定条目按开头日期排，无日期不留标签、正文占满；明确写明当前不用人做的条目收在可展开说明中，不计入等待数；成员卡派驻只显示首个中英分号前一句，悬停可看全文；任务书、交付、日志与审核共同确定岗位、派驻、步骤与明确起止耗时。成品文件在，看板才标为“收到”。只有 `-说明.md` 或 `-notes.md` 时，看板显示说明文件首行写明的未完成情况或卡点。说明写了“完成”，成品文件却不在，也不算收到。最新审核未通过的留在在干的活并标红退回，做成了只列最新审核通过且日期在最近七天的交付；计数只数通过的，首审证据不足不显示一次过比例。用 `--today YYYY-MM-DD` 固定含当天的七天窗口；无文内日期时用交付文件日期，计数旁注明按文件时间。派出或在跑算忙，按名册显示岗位，并链接已有完整组织图。脚本用标准库离线生成单文件；文件变了，重新生成就更新。

## 周报卡和存成图片

生成和核对卡片、图片都用技能自带脚本，不在人的项目中新建生成或检查脚本。临时检查用命令行内联命令或系统临时目录，不在项目中留下检查脚本。

人说“出周报卡”时，从技能包根目录运行：

```bash
python -X utf8 skills/fleet-chart/scripts/fleet_weekly.py --project <项目目录>
```

默认放在看板旁边：中文 `fleet/周报卡.html`，英文 `fleet/weekly.html`；语言与看板同样自动判断，`--lang zh|en` 可覆盖。用 `--today YYYY-MM-DD` 固定含当天的最近 7 天；它按当前留存文件计算，不还原历史项目快照。例如复核过去某一周时，`--today` 填那一周的最后一天，不要补造审核日期。打开页面，核对项目名、日期范围、模型数和四个数的依据，再点“存成图片”保存 PNG；页面也提供 PNG 预览，浏览器没有直接下载时可从预览保存。

四个数沿用看板对任务书、交付、审核和项目卡的读取方式，并读取既有决定记录；首审依据还可来自项目内已有说明文件中的明确链接。做完几单只数最近 7 天最新审核通过的任务，同一单修订不重复算。一次过审占比是本周审核通过且明确记录第一次审核就通过的单数，除以本周审核通过的单数。首审声明采用审核报告里的“审核轮次：1”“Review round: 1”等明确标记，也采纳项目内已有 `README.md`、`README.zh-CN.md` 中标签为“第一轮审核”“首次审核”“First review”或“Initial review”、并指向现有舰队审核报告的 Markdown 链接；同份报告的重复声明合并，声明冲突或缺首审证据时不猜比例，分母为 0 不显示百分比。曾被退回不能证明那次是首审，不从 README 叙述或表格推测审核日期；日期仍沿用看板读取结果及明确标注的文件时间。

审核抓到几处错只数窗口内未通过审核中的必改问题，建议不计。有逐项审核表时，数结果明确为“不通过”的行，不再重复数后面的整改清单；没有该表时，数“必修项”“Required fixes”等明确必改清单，排除其中标为建议或可选的条目；一般“问题”“Issues”清单中，只有明确写了“必改”“must”等必改要求的条目才计。不把整改子步骤或普通核查项当成新问题。例如一份审核表有两行“不通过”，计 2；必修清单里有一条写的只是建议压缩篇幅，不另计。

问了你几次合计两处现有记录：窗口内决定日志 `fleet/决定.md`（英文 `fleet/decisions.md`）中明确由人作决定的条目，加上当前项目卡“等我定”中窗口内新记、仍留存的提问条目。决定日志按每条决定计一次，日期读标题，“谁定”或“Decision maker”须明确为“人”“Human”“User”“用户”“使用者”或“人类”；同条还列了项目岗位时，明确由人作决定仍计一次。仅由模型或项目岗位作的决定、窗口外条目和明确不用人做的说明不计。缺决定者身份或有效日期时，准确总数未知；仍把窗口内完整有效的记录计为下限，至少 1 条时显示“≥N”，下限为 0 时显示“—”，并说明漏计几条及原因。两处来源都没有记录时才写“还没有记录”。已回答且移出项目卡的事项由决定日志补充，未写入日志的历史提问仍无法还原，所以这个数只代表已有记录，不声称是全部打扰次数。

卡面和 PNG 用简短、人能直接看懂的话解释数字；有记录但证据不足时显示“—”和原因，只有“问了你几次”可按上述规则显示下限，不把未知写成 0。文件来源、计数口径及缺口的详细说明放在卡片下方的 HTML 中，不画进 PNG。无文内日期而沿用交付文件时间时，说明中明确标注日期来源。舰队模型数从名册“派驻”首个中英分号前的标识去重；明确写了“模型 A：…”等别名时按别名合并，不按岗位数或工具名推算厂商。

人说“把组织图存成图片”时，保留上面的 Mermaid 用法，另从同一份名册生成本地卡片页：

```bash
python -X utf8 skills/fleet-chart/scripts/fleet_org_card.py --project <项目目录>
```

中文默认写 `fleet/组织图.html`，英文写 `fleet/chart.html`，`--lang zh|en` 可覆盖；打开后逐岗核对，再点“存成图片”。名册缺失时页面说明还没有记录，不凭聊天补成员。卡片直接以 SVG 画项目名、岗位、派驻和汇报关系，用户文字经过转义；存图在浏览器中将 SVG 画到 canvas，再用 `canvas.toBlob` 生成 PNG，不使用 `foreignObject`、外部脚本或外部字体，也不联网。这样避开 Safari 对 `foreignObject` 的限制。交回时写明实际测试过哪些浏览器；设计选择本身不算浏览器测试。周报和组织图采用独立脚本，便于分别生成和发布可用页面，不给看板和状态栏带入 SVG 或存图资源；共同复用已有读取代码，避免同一记录出现不同解析。两个脚本都只读已有项目记录、离线生成单文件；记录变了就重新生成，不要求为了卡片另记一套数。遇到输出已存在，先核对是否应另起版本。

仅供 Claude Code：想在底部常显同源的一行状态，先征得使用者同意，再将 `"statusLine": {"type": "command", "command": "python .claude/skills/fleet-chart/scripts/fleet_board.py --status-line", "refreshInterval": 60}` 合并进项目 `.claude/settings.json` 或用户 `~/.claude/settings.json`；保留其他设置，安装器不改设置。`refreshInterval` 单位是秒，状态栏也随新回复等事件更新；Windows 命令路径用正斜杠，经 Git Bash 运行，未安装时用 PowerShell。`--status-line` 只读所需文件、只输出一行，不写文件；项目目录先取 `--project`，否则取输入 JSON 的 `workspace.project_dir`，再否则用当前目录，语言与看板同样自动判断。
