# 发前检查

用项目词表扫描这次要发的文件。审核者逐项回到原处核对命中，再打开最终成品检查，由项目授权的发布人决定能否发出。检查工作派给名册里的成员时，项目经理负责验收检查结果。

先确定本次会发出的文件，再请读者提供或确认自己的词表。词表由项目维护，涵盖内部代号、人名、路径、金额和夸大说法；[示例词表](terms.example.txt) 只展示格式，不能代替项目的真实检查规则。真实敏感词表保留在读者自己的项目内，不随公开材料发出。

每行三列，用一个制表符分隔：级别（ERROR 或 WARN）、Python 正则、说明；空行和以 `#` 开头的注释跳过。正则默认区分大小写，需要时用 `(?i)`。说明写应该怎么处理，避免再次复制敏感内容。正则中的竖线不分列。

从技能包根目录运行；将末尾文件参数换成本次明确选定的文件，脚本不递归寻找文件：

```bash
python -X utf8 skills/fleet-precheck/scripts/precheck.py --terms skills/fleet-precheck/terms.example.txt /path/to/my-project/fleet/交付/年度摘要.md
```

每个命中逐行报告级别、文件、行号和说明；不回显原文。Markdown 中反引号或波浪号围栏代码块里的示例跳过，行内代码仍检查；未闭合围栏直到文件末尾都按代码处理，因此另须人工核对围栏是否正确。对外文稿中的代码也要由人检查，不能借围栏藏正文。

退出码：0 表示没有 ERROR，仍须处理 WARN；1 表示有 ERROR；2 表示配置或文件读取失败，本次检查无效。修正 ERROR，逐项确认 WARN 的处理或保留理由，修改后重跑。最后核对所有将发出的文件都已检查，并核对事实出处、引用、授权及最终呈现。词表未命中不证明内容正确，也不代表已经获得发布授权。

完成后交回检查命令、输出摘要、已处理问题和仍需人定的事项。遇到阻碍时，一次只带人做一步：

- 没有有效词表：说明示例不能代替本项目的发出规则，先只请人在这里回现有词表的项目内相对路径，或回“还没有”。没有就由 AI 在指定项目内备好词表，先拟第一条不敏感的规则请人确认。敏感规则则给出实际本地路径和只留敏感部分待补的那一行，请人在自己的编辑器里只补这一处，回“好了”，不贴词条。先核对已存规则的格式，再这样带人补下一条必需规则。已有词表格式不对，就指出第一处需改的行号和具体改法，不回显内容，请人改完回“好了”，再核一次后运行检查。
- 文件读不到：先只读核对所选路径。确实要人帮忙时，写出完整路径，请人在自己的文件管理器中打开，回“能打开”或“找不到”，不贴正文；收到后重试读取。若只有人的电脑能打开，就给出已填好实际路径的完整检查命令，请人在自己的终端运行，只回退出码和诊断信息，再核对结果是否覆盖本次选定的文件。
- 授权不足：说清哪项动作需要人定、为什么，请确认人在这里明确回复同意这项动作或允许的范围。先按项目审批流核对并记录回复，再继续。定方向、对外承诺、花钱和删东西先由人点头；对外发出本身也按该审批流决定。

不索要密钥或密码。回复还没解决当前阻碍，就给下一步，不从头再问。
